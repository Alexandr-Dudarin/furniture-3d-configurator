# Loading v1: проверка

21 сентября 2026 года. Локальная восстановленная копия проекта после studio
scene v1; доступ к Git на Windows пользователя не использовался.

## Автоматические проверки

- Vitest: 195 тестов, 23 файла, успешно.
- TypeScript и production build: успешно.
- ESLint изменённых TypeScript/TSX файлов: успешно.
- Общий lint ранее имел 11 замечаний-ошибок в неизменённых файлах:
  10 `no-explicit-any` в export_preview_states двух круглых моделей и
  `react-hooks/set-state-in-effect` в CustomSelect. Этот этап их не исправляет.
- Граф production chunks проверен: начальный статический граф не включает
  модули Three.js; SceneView находится за динамическим импортом.
- Проверены отдельные превью всех отделок, совпадение цветов металла sRGB,
  ограничения кэша по байтам/количеству, объединение запросов, ошибки,
  позднее завершение после clear и независимость ресурсов экземпляров GLB.
- Проверено освобождение ImageBitmap после замены встроенного материала и
  отсутствие повторного close. Контроллер прекращает новые запросы после dispose.

## Браузер

Chromium 153, WebGL через программный SwiftShader. Основной экран 1440 × 920,
мобильный 390 × 844. Браузерная сборка содержит временные диагностические
ссылки на сцену/хранилище; в поставляемом приложении их нет.

Проверено:

1. Задержка загрузки модуля 3D: интерфейс и ввод размеров уже работают,
   смена режима во время ожидания приводит к показу последней конфигурации.
2. Ошибка модуля 3D: перезагрузка страницы с сохранением выбранной сборки.
3. Ошибка GLB и ошибка normal-карты: повтор загрузки восстанавливает модель.
4. Два последовательных прохода по всем 13 покрытиям: одинаковые счётчики
   GPU на соответствующих шагах, 1 мебельная группа в сцене, кэш шаблонов
   не превышает 96 MiB. Для U-frame: 4 геометрии, 7 текстур в обоих проходах.
5. Все пять оснований; камера и окружение сохраняют идентичность. Повторно
   выбранные недавние GLB используют кэш байтов.
6. Все шесть готовых моделей; повторные посещения с проверкой GPU-ресурсов.
7. Числовой ввод высоты, обновление страницы и открытие ссылки в новом
   контексте браузера восстанавливают конфигурацию.
8. Мобильная сцена и панель отображаются корректно.

В проверках поведения не было необработанных ошибок JavaScript. Искусственно
вызванные сетевые ошибки логируются ожидаемо и имеют путь восстановления.

## Сохранность изображения

Попиксельно сравнивалась 3D-область x=376…1439, y=0…919, при одинаковом ракурсе
и одинаковых параметрах. Разница RGB равна нулю:

- белый мрамор с золотым рисунком, круг, V-основание;
- чёрный мрамор с золотым рисунком, круглая рифлёная опора;
- натуральный дуб, реечное основание;
- готовая First Table с исходной отделкой;
- сборная столешница с чёрным мрамором и белыми U-рамами.

Интерфейс не входит в это попиксельное сравнение: карточки теперь используют
превью. Исходные PBR, GLB, настройки освещения и сохранённый формат не менялись.

## Ограничения измерений

Размеры JS в документации взяты из обычного `npm run build`, без диагностических
вставок. Запросы проверялись в браузере, размеры превью — по реальным файлам.
Resource Timing этой среды возвращал нулевые поля размера передачи, поэтому
сетевую экономию не выдаём за измеренный transferSize. Объём исходных файлов
и количество URL — отдельные проверяемые показатели. FPS, время первой модели
на реальном телефоне и весь RSS/heap браузера не измерялись как продуктовые
гарантии; программный GPU не подходит для таких обещаний.

Стабильность renderer.info.memory и ограничение кэша не являются доказательством
отсутствия всех возможных утечек браузера. Первое локальное открытие и материалы
нужно дополнительно принять в обычном браузере пользователя.
