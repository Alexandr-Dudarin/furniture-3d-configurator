# Исходники модулей столов — modular-tables-v6

Основания извлечены из принятых production GLB без изменения геометрии,
UV, локальных transforms или preview-материалов:

- `public/models/first-table.glb` → `public/modules/bases/four-legs.glb`;
- `public/models/table-03-slat-pedestal.glb` → `public/modules/bases/slat-pedestal.glb`;
- `public/models/table-05-round-fluted-pedestal.glb` → `public/modules/bases/round-fluted.glb`;
- `public/models/table-02-u-frame.glb` → `public/modules/bases/u-frame.glb`;
- `public/models/table-04-v-pedestal.glb` → `public/modules/bases/v-pedestal.glb`.

Экстрактор не меняет исходные GLB. Перед извлечением table-03 исправлен своим
Node-генератором: нижняя часть ядра продлена в площадку, закрывая зазор 6 мм.
Оба генератора table-03 (Node и Blender) содержат это изменение.
Исходные table-01 и table-05 неизменны.

Повторить извлечение из корня проекта:

```bash
python assets/source/table-modules/extract_bases.py
```

Нужен Python 3 со стандартной библиотекой, без Blender и сторонних Python-пакетов.
Скрипт переносит только используемые nodes, meshes, materials, accessors,
bufferViews, textures и images. Прежняя столешница удаляется; неиспользуемые
бинарные данные не попадают в модуль. Добавляется attachment node.

Отдельные GLB оснований можно импортировать в Blender через glTF 2.0.
Столешница модульного режима генерируется в приложении; её воспроизводимый
исходник — `src/three/tableAssembly/tabletopGeometry.ts`. Готового GLB каждой
комбинации и функции экспорта сборки в этой версии нет.

Runtime-паспорт пяти оснований, метрика UV, размеры, высота, крепление,
материалы и контракт поставки следующих модулей:
`docs/table-module-standard-v1.md`.

Приложены отчёты glTF Validator и снимки реально собранных вариантов в браузере.
Информационное сообщение `NODE_EMPTY` ожидаемо для `Attachment_Tabletop` — это
служебная точка крепления, которая не должна содержать Mesh.

Четыре ножки меняют высоту в runtime через `cornerLegs.ts`, без морфов.
Четыре копии исходных вершин используются для пересчёта, без накопления деформации.
Неиспользуемые UV/тангенты металлических ножек сохранены из исходного GLB:
Validator сообщает о них как INFO, поскольку материал не имеет текстур.

Снимки с суффиксом `-v2.png` относятся к этапу modular-tables-v2; `rounded-slat.png`
и `round-fluted-tall.png` — исторические снимки v1.

В modular-tables-v3 GLB и исходники геометрии не меняются. Оба регулируемых
основания имеют диапазон 640–840 мм, шаг 10 мм. Каталог разделяет исходный
`sourceHeight` GLB и начальное значение `height.base` для пользователя.
На круглой опоре это соответственно 738 и 740 мм; трансформации считаются от 738 мм.


В modular-tables-v4 добавлены U-рамы и V-основание. Шесть готовых моделей
и три прежних GLB-модуля остаются побайтово прежними. Экстрактор для V-основания
удаляет девять явных узлов столешницы, сохраняя `UnderTop_Mount`.
Новые модули — без текстур столешниц, камер, света или пола.

U-рамы в сборке: высота 640–840 мм / шаг 10 мм, расстановка по габаритам и
форме, сохранение сечения и фасок. V-основание в сборке: высота фиксирована
743 мм; монтажная площадка проверена для всех семи форм. Его наклонные опоры
не растягиваются. Отдельные паспорта: `u-frame-passport.md`, `v-pedestal-passport.md`.
Снимки `*-v4.png` показывают новые модули в реальном браузере.


В modular-tables-v5 добавлен выбор профиля **параметрической столешницы**:
фаски 1/5 мм, R5 и полукруглый торец. Исходники: `tabletopGeometry.ts` и
`tabletopEdgeProfile.ts` в `src/three/tableAssembly/`. Все GLB, их исходники
и текстуры остались прежними; повторное извлечение оснований не требуется.
Документ `docs/table-module-standard-v1.md` обновлён до v1.4.
Снимки `edge-*-v5.png` показывают профили в браузере; четыре снимка деревянного
стола сделаны при одной толщине 50 мм и одинаковом положении камеры.


В modular-tables-v6 исправлена только прежняя полукруглая кромка: теперь это
узкий полуэллипс с непрерывным рисунком на верхнем стыке. Размеры и ID сохранены.
Сравнение `soft-edge-before-v6.png` / `soft-edge-after-v6.png` снято при одинаковых
материале, камере, освещении и размерах. В кадре before используется геометрия v5;
интерфейс в обоих кадрах уже v6. Остальные `*-v6.png` показывают новый интерфейс.

Карточки оснований `public/previews/bases/*.png` отрендерены из GLB модулей
в нейтральном сером материале. Превью показывает форму, покрытие выбирается
независимо. Нужные материалы берутся из существующих `base-color.jpg`.

Для повторного рендера превью (не требуется при установке обновления):

```powershell
$env:PREVIEW_PLAYWRIGHT_PATH = 'file:///D:/qa-tools/node_modules/playwright/index.mjs'
$env:PREVIEW_CHROMIUM_PATH = 'D:/qa-tools/chromium/chrome.exe'
node assets/source/table-modules/render_base_previews.mjs
```

Пути заменить на свою среду с Playwright и Chromium. Проект использует свои
Three.js и Vite, в зависимости приложения Playwright не добавляется. Для среды,
где Playwright доступен стандартным импортом, а браузер установлен им, обе
переменные можно опустить. Результат: пять PNG 320 × 240, пути уже прописаны в UI.
Все GLB, PBR-текстуры и экстрактор остаются прежними. Контракт модулей — v1.5.
