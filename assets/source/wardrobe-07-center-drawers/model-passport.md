# Паспорт: Шкаф с центральными ящиками

## Статус

- ID: `wardrobe-07-center-drawers`.
- Тип: constructor-ready geometry; review package.
- Runtime geometry: **Supported by current engine**.
- Полная материал/UV-интеграция: **Requires engine extension**.
- Размеры Ш × В × Г: **1601 × 2052 × 480 мм**; 1 unit = 1 meter.
- Front: +Z; X — ширина, Y — высота, Z — глубина; root (0,0,0), floor Y=0.
- Height: `height-configurable`. Толщина плит: `thickness-fixed`.
- Две высокие боковые двери, две короткие центральные, три ящика. Две боковые верхние полки со штангами, две центральные полки и панель над ящиками.

## Фиксированные размеры и допущения

Плиты и фасады 16 мм; задняя стенка 4 мм; дно ящика 6 мм; цоколь 60 мм; скругление 0.7 мм; обычный межфасадный зазор 3 мм; монтажный зазор полки 0.5 мм с каждой стороны; отступы полок от передней/задней плоскостей корпуса по 8 мм. Штанги Ø25 мм. Ручки 08: 1000 × 12 × 12 мм, общий выступ 28 мм.

У 07 пользователь отдельно выбрал глубину 480 мм вместо 462 из карточки. Верх панели над ящиками находится на 760 мм от пола; высота нижнего блока постоянная. Фасады трёх ящиков одинаковой высоты 217.333333 мм; углублённые полосы захвата — 15 мм. Короткие двери начинаются с 761 мм от пола.

Глубина 08 включает выступ ручек в закрытом состоянии — согласованное в плане допущение. Точный оттенок, скрытая фурнитура, толщины, отступы, углы открытых технических видов и устройство ручек оценены по фото, а не измерены у производителя. Подвижные механизмы не заявлены как заводская кинематическая копия.

## Конструкция и поведение

Боковины ±W/2 с учётом толщины; перегородки по X=±W/4. Полезные просветы: W/4−1.5t / W/2−t / W/4−1.5t. Подвижные детали получают локальные `delta-move`, оболочечные сегменты — `stretch-segment`; fixed-детали не вложены в scale-target.

| Узлы | Поведение |
|---|---|
| `Panel_Side_Left/Right` | Ширина: движение; высота и глубина: полезное растяжение |
| `Panel_Divider_Left/Right` | ±ΔW/4, полезные H/D; толщина постоянная |
| `Panel_Top`, `Panel_Bottom`, `Panel_Back`, `Plinth_*` | Полезные длины; крыша поднимается; низ остаётся на полу |
| `Shelf_*` | Постоянная толщина; полезные W/D; уровни по согласованному правилу |
| `Door_*_Hinge` | Отдельная вертикальная ось Y у предполагаемых петель, без scale |
| `Door_*_Panel` | Размеры полотна, кромки и зазоры контролируются отдельно |
| `Handle_*_Assembly` | Сосед полотна в hinge-группе; размеры ручек постоянные |
| `Drawer_*_Assembly` (07) | Самостоятельные короба с осью +Z; детали короба регулируются отдельно |
| `ClothesRail_*` | Растёт только длина; Ø25 мм постоянен |

Имена `*_Tile_*` — управляемые части оболочки каждой плиты. Их локальные оси X/Y/Z не повёрнуты. Девять частей сохраняют скругления: центральные участки растягиваются, края/углы перемещаются. Наклонных силовых элементов нет. Цилиндры штанг имеют запечённую геометрию с продольной X; local transforms без отрицательного scale.

В 07 две центральные полки делят полезную высоту над блоком ящиков на три просвета; боковые полки совпадают с верхней. В 08 четыре полки делят боковые секции на пять просветов, центральная верхняя совпадает с верхними боковыми. Штанги находятся на 75 мм ниже центра полки. Количество деталей при resize не меняется.

## Материалы и UV

Целевые slots: `carcass`, `fronts`, `hardware`. Семантические группы называются `Board_*`, `Front_*`, `Hardware_Metal`; полный точный список в `model-contract.json → materialTargets` и `BOARD_MATERIAL_TARGETS` конфига. Один target принадлежит одному slot. Исходный ЛДСП имеет metalness 0, roughness 0.62; цвет `#636563` интерпретирован как sRGB и преобразован в linear при экспорте.

Плоские карты 1×1 для исходного однотонного материала намеренные: neutral color, normal GL, metallic/roughness. Они сохраняют корректный PBR и UV без выдуманного текстурного рисунка. Геометрические UV заданы в метрах (1 UV/m), широкие поверхности и торцы разделены, для скруглений используется длина дуги. V соответствует основному направлению волокон детали; U — поперечному/толщине на кромке.

`model-contract.json → uvContract` хранит для каждого material target отдельно U/V: dimension, baseLength, stretchFactor, translationFactor, anchor. Требуемое преобразование:

```text
repeat = (baseLength + delta × stretchFactor) / baseLength
offset = anchor × (1 − repeat) + delta × translationFactor
```

Translation сохраняет фазу рисунка на перемещаемых фиксированных кромках. Общий runtime пока не поддерживает этот контракт. Поэтому основной `textureAxes` пустой и textured resize не заявляется готовым. Проба текущего API на реальном GLB дала ошибку размера рисунка **8.626069%** по высоте выбранного фасада. Подробности — `runtime-compatibility.json` и корневой `INTEGRATION_REQUIREMENTS.md`.
