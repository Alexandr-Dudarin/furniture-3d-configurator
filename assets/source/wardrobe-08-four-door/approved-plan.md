Пользователь подтвердил глубину шкафа 07 **480 мм**. Прежнее расхождение 462/480 закрыто; 462 мм больше не используется для этой модели.

Для модели 08 предлагается считать глубину внешним размером закрытого изделия **включая выступ ручек**, чтобы фактический bounding box GLB совпадал с паспортом. Карточка отдельно не определяет способ измерения ручек; это проектное допущение.

## 3. Конструкция по фотографиям

**Шкаф 07:** три секции; две высокие боковые двери, две короткие центральные двери, три центральных ящика. В каждой боковой секции одна верхняя полка и штанга под ней. В центральной секции две полки выше ящиков и отдельная горизонтальная панель над блоком ящиков. Ширины модулей приблизительно 1:2:1; числа 400/800/400 из схемы не принимаются за внутренние просветы.

**Шкаф 08:** три секции; четыре полноразмерные двери и четыре длинные вертикальные ручки. По открытому виду — четыре полки в каждой боковой секции, одна верхняя полка и штанга в центральной секции. Ящиков нет.

Число дверей, секций, полок и ящиков фиксировано в первом пакете.

## 4. Предлагаемые постоянные размеры и правила

Эти значения оценены для моделирования; на референсах они не измерены.

| Элемент | Предложение |
|---|---|
| Боковины, крыша, дно, перегородки, полки, фасады | Плита 16 мм; толщина не регулируется |
| Задняя стенка | 4 мм; самостоятельная деталь |
| Цоколь | 60 мм; постоянная высота |
| Короб ящика | Стенки 16 мм, дно 6 мм |
| Зазоры между обычными фасадами | 3 мм; постоянные |
| Захват ящиков 07 | Отдельные горизонтальные углубления/отступы порядка 15 мм по виду референса; без добавленных наружных ручек |
| Штанги | Круглое сечение Ø25 мм; диаметр постоянный |
| Ручки 08 | Около 1000 мм длиной, профиль около 12 мм, общий выступ около 28 мм; постоянные размеры |
| Нижний блок 07 | Верх разделительной панели на высоте 760 мм от пола, включая цоколь; высота блока постоянная |

**Ширина:** центры двух перегородок находятся на X = −W/4 и +W/4. Наружные грани боковин — на ±W/2. При толщине `t` внутренний просвет боковой секции равен `W/4 − 1.5t`, центральной — `W/2 − t`. Так сохраняются модульные пропорции 1:2:1 и постоянная толщина плит. При `t = 16` базовые просветы шкафа 07 — 376.25 / 784.5 / 376.25 мм; шкафа 08 — 376 / 784 / 376 мм. Полки получают собственные монтажные зазоры относительно этих просветов.

**Высота 07:** цоколь и нижний блок остаются на месте. Высоты трёх ящиков не растут. Прибавка высоты распределяется по верхней центральной секции; две её полки делят пространство над разделительной панелью на три просвета с учётом толщин. Верхние боковые полки располагаются на одном уровне с верхней центральной полкой; штанги следуют за ними с постоянным отступом. Боковые двери растут по высоте, центральные — только в пределах верхнего блока.

**Высота 08:** четыре боковые полки делят полезную высоту на пять просветов с учётом толщин. Центральная верхняя полка совпадает по высоте с верхней боковой; штанга остаётся под ней на постоянном расстоянии. Ручки сохраняют длину и отступ от нижнего края дверей.

**Глубина:** задние и передние сборки смещаются на ±ΔD/2; полезная глубина панелей, полок и коробов изменяется на ΔD с сохранением толщин и отступов. Фасады и ручки перемещаются к передней плоскости без растяжения своей толщины.

Скрытый крепёж, точное устройство захвата дверей 07 и направляющие не воспроизводятся как измеренные заводские детали. Видимая фурнитура и места будущих шарниров выделяются отдельно.

## 5. Иерархия и правила текущего движка

Root: `Wardrobe_07_Root` / `Wardrobe_08_Root`; position = 0, rotation = 0, scale = 1. Передняя сторона +Z, пол Y = 0. Все управляемые локальные оси совпадают с X/Y/Z, кроме намеренно ориентированных цилиндров штанг.

| Группа деталей | Пример имени | Правила |
|---|---|---|
| Боковины | `Panel_Side_Left`, `Panel_Side_Right` | Move X ±ΔW/2; stretch Y/Z по полезным длинам; move Y +ΔH/2 для сохранения низа |
| Перегородки | `Panel_Divider_Left`, `Panel_Divider_Right` | Move X ±ΔW/4; stretch Y/Z с сохранением толщины |
| Крыша, дно, цоколь | `Panel_Top`, `Panel_Bottom`, `Plinth_Front` | Stretch полезных X/Z; крыша move Y +ΔH; дно и высота цоколя фиксированы |
| Задняя стенка | `Panel_Back` | Stretch X/Y, move Z −ΔD/2; толщина фиксирована |
| Полки | `Shelf_Left_01`, `Shelf_Center_01`, … | Stretch X с коэффициентом 1/4 или 1/2; stretch Z; move X и Y согласно секции |
| Двери | `Door_Left_Hinge` → `Door_Left_Panel`, … | Hinge-группа только перемещается; полотно отдельно растягивается по полезным X/Y и смещается относительно петли |
| Ручки | `Handle_Left`, … | Соседи полотна внутри hinge-группы; собственные размеры фиксированы, положение следует за краем двери |
| Ящики 07 | `Drawer_01_Assembly`, … | Сборка без scale; передняя панель, стенки и дно изменяются отдельными правилами по W/D; высота фиксирована |
| Штанги | `ClothesRail_Left`, … | Продольное растяжение и перемещение; сечение не меняется |

Каждая сборка получает уникальные имена. Fixed-детали не помещаются внутрь растягиваемого узла. Для сохранения маленьких кромок при resize используются отдельные профили/сегменты там, где единый scale исказил бы фаску.

Для геометрии подходят `delta-move`, `edge-anchor`, `stretch-segment` и fixed-детали. Полезная длина задаётся как `L = L₀ + (dimension − base) × factor`, а не масштабированием всего шкафа.

Статус высоты: планируется `height-configurable`. Толщины плит: `thickness-fixed`. Открывание дверей, выдвижение ящиков и изменение числа полок не включаются в UI первого пакета. Петли и drawer assemblies готовятся; открытые технические виды создаются в проверочном окружении.

## 6. Материалы

Планируются три независимых пользовательских slot:

- `carcass` — корпус, внутренние полки, перегородки, внутренние детали ящиков;
- `fronts` — дверные полотна и лицевые панели ящиков;
- `hardware` — ручки и видимая фурнитура.

Несовместимые UV-поверхности разделяются на самостоятельные semantic targets внутри slot: плоскости панелей и кромки, боковые/центральные полки, высокие/короткие фасады, фиксированные по высоте фронты ящиков. Один material target принадлежит только одному slot. Волокна фасадов ориентируются вертикально; кромки имеют UV по реальным размерам, а не квадратную картинку на толщине 16 мм.

Исходный GLB может иметь неметаллический матовый серый материал ЛДСП (`metalness = 0`). Оттенок — визуальное приближение к фото, не известный заводской декор.

**В текущем общем каталоге нет однотонных board finishes.** Для сохранения серого вида после загрузки приложения центральному чату нужно добавить реальные материалы ЛДСП, например серый, белый и графитовый, с согласованными ID. Эти ID пока не используются в TypeScript-конфиге как существующие. Окрашенный металл не подставляется вместо ЛДСП.

Для фурнитуры уже доступны `metal-black-matte`, `metal-white-matte`, `metal-anthracite`. Древесные декоры корпуса/фасадов можно подключать после решения проблемы UV ниже.

## 7. Подтверждённое ограничение UV — Requires engine extension

В свежем архиве прежнее повторное применение UV-компенсации при смене соседнего slot исправлено: `refreshTextures()` восстанавливает базовый repeat/offset перед повторным захватом.

Однако текущий `FurnitureController` по-прежнему вычисляет texture repeat как `dimension / dimensionBase`. Для детали с постоянным вычетом толщин, зазоров или высоты блока ящиков нужен коэффициент **собственной полезной длины детали**:

```text
геометрия: scale = (L₀ + (dimension − base) × factor) / L₀
текущий UV: repeat factor = dimension / base
```

Эти коэффициенты различаются. Разделение material targets само по себе это не исправляет: в `MaterialTextureAxisBinding` сейчас можно задать только U/V, без `baseLength` и `factor`.

На неизменённом реальном контроллере выполнена небольшая проверка с синтетическим фасадом, без создания модели шкафа:

| Показатель | Результат |
|---|---:|
| Высота шкафа: base → max | 2.052 → 2.400 м |
| Полезная высота фасада: base → max | 1.288 → 1.636 м |
| Требуемый множитель UV | 1.2701863354 |
| Фактический множитель UV | 1.1695906433 |
| Увеличение размера рисунка | **8.6009%** |
| Возврат scale и repeat к base | 1 и 1 |

Это отдельная несовместимость с изменением полезных длин, а не возврат ранее исправленной ошибки `refreshTextures`.

**Задача центральному чату:** добавить общее декларативное UV-поведение по полезной длине (`baseLength`/`factor`) либо проверенному масштабу соответствующего узла. Расширение должно работать для любых моделей, сохранять базовые repeat/offset и независимость slot, поддерживать отдельные U/V. Новый формат контракта сначала согласуется и проверяется в общем runtime, затем используется моделями. Искусственные UI-размеры, условия по modelId и model-specific шейдеры для обхода проблемы не предлагаются.

До этого расширения геометрию и серые исходные материалы можно подготовить для ревью, но нельзя объявлять весь пакет с древесными текстурами полностью совместимым с текущим движком.

Дополнительно общий UI сейчас печатает метры через `toFixed(2)`: он скроет точность 1601/2052 мм и шага 1 мм. Центральному чату предлагается форматирование по step либо отображение миллиметров. Это не меняет точность геометрии.
