# Шкаф 15 — «Катания-4.2»

В приложении начальная глубина и сброс модели — **450 мм** (`model-spec.json → defaults.depth`).
Геометрическая база GLB остаётся 400 мм: `dimensions.depth.base` — опора resize,
`defaultValue` — начальная настройка. Генератор переносит обе величины в каталог
и runtime; менять `base` ради другого стартового размера нельзя.

Параметрическая модель по четырём приложенным референсам, стандарт v2.7. База Ш × В × Г: **1600 × 1900 × 400 мм**. Диапазоны: 1600–2400 / 1900–2700 / 400–600 мм, шаг 1 мм.

Четыре фрезерованных фасада, четыре равных отделения с верхними полками и торцевыми кронштейнами. Корпус, фасады и ручки имеют независимые покрытия из существующего каталога проекта. Двери используют уже реализованное открывание; доступен вид наполнения.

## Передача и подключение

Модель подключена в конструктор обновлением `wardrobe-15-katania-v1`.
Описание и результаты интеграции: `docs/wardrobe-15-katania-v1.md` и
`docs/wardrobe-15-katania-v1-validation.md` от корня проекта.

В `incoming-package/` сохранены инструкция, manifest и SHA256 исходного
model-only пакета. Эти контрольные суммы описывают входящие файлы. При
интеграции добавлены два существующих покрытия в генератор и сгенерированные
описания каталога/runtime; production GLB остался прежним.

Точки входа:

- `public/models/wardrobe-15-katania-four-door.glb` — модель для браузера.
- `src/three/models/wardrobe-katania-four-door/catalog.ts` — лёгкий каталог для registry.
- `runtime.ts` в той же папке — ленивый экспорт полного определения.
- `config.ts` — размеры, resize rules, affine UV, материалы и двери.
- `wardrobe.test.ts` — проверки реального GLB существующими контроллерами.

## Воспроизводимость

Команды выполняются из корня актуального проекта после подключения файлов пакета в отдельной интеграционной ветке:

```sh
npm ci
npm ci --prefix assets/source/wardrobe-15-katania-four-door
node assets/source/wardrobe-15-katania-four-door/build_model.mjs
node assets/source/wardrobe-15-katania-four-door/validate_model.mjs
npm test -- src/three/models/wardrobe-katania-four-door/wardrobe.test.ts
```

`build_model.mjs` — канонический автономный генератор этой модели. Он читает `model-spec.json`, создаёт production GLB, mesh-source, model-contract, performance и три TypeScript-файла модели. Общие файлы проекта он не меняет. Для изменения конструкции редактировать генератор и спецификацию, затем пересоздавать связанные результаты вместе; прямые правки сгенерированного `config.ts` будут потеряны.

`mesh-source.json` содержит точные вершины, нормали, UV, индексы, материалы и иерархию. `model-contract.json` содержит детали, коэффициенты, четыре оси дверей, материал-таргеты и контракты UV. `runtime-contract.md` фиксирует принятые конструктивные решения.

## Сцена Blender

В среде создания пакета Blender отсутствовал; `.blend` и проверка Blender roundtrip не заявлены. Предоставлен воспроизводимый скрипт, его Python-синтаксис проверен.

На компьютере с Blender 4.x выполнить:

```sh
blender --background --python assets/source/wardrobe-15-katania-four-door/create_model.py
```

Он восстановит редактируемую сцену из mesh-source, сохранит настоящий `.blend`, экспортирует отдельный `*-blender-check.glb`, реимпортирует его в чистую сцену и создаст `blender-verification.json`. После запуска проверить поверхности, UV и pivots в Blender. Контрольный GLB не подменяет production-файл автоматически.

## Изображения проверки

```sh
node assets/source/wardrobe-15-katania-four-door/prepare_previews.mjs
python -m pip install -r assets/source/wardrobe-15-katania-four-door/requirements-preview.txt
python assets/source/wardrobe-15-katania-four-door/render_previews.py
```

Экспорт состояний использует production GLB и реальные контроллеры проекта. CPU-рендер читает эти состояния и существующие изображения древесины из проекта. `preview-states.json` содержит 15 состояний; PNG показывают базу, промежуточный и максимальный размеры, возврат, открывание, наполнение, смену материалов, профиль и петлевую кромку. В кадре `profile-detail` первый фасад изолирован для обзора сечения. Это геометрические превью; они не заменяют финальную проверку WebGL и FPS.

Рендеру нужен шрифт DejaVu Sans; путь задаётся в функции `font()` для ОС запуска. Обычному использованию модели Python, Blender и authoring-зависимости не нужны.

## Принятые ограничения

- Торцевые кронштейны остаются при любой глубине 400–600 мм. Автозамены на поперечные штанги при 500 мм нет; выдвижение кронштейнов не анимировано.
- По 48 канавок на двери: ширина 3 мм, глубина 1,8 мм и фаски 0,25 мм постоянны; с шириной шкафа растут плоские промежутки.
- Толщины, профиль канавок, длина ручек и упрощённая фурнитура — оценки по изображению, не заводская деталировка.
- Для общей глубины учтён выступ закрытых ручек 28 мм.
- Источники данных, точные допущения и ограничения проверки перечислены в паспорте и validation report.
