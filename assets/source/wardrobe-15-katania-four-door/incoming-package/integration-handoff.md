# Подключение шкафа 15 «Катания-4.2»

Этот model-only пакет предназначен центральному чату разработки конструктора. Он подготовлен по стандарту **v2.7** на архиве `furniture-3d-configurator под архив (2).zip`, полученном 22.09.2026.

SHA-256 исходного ZIP: `18dc7a516c8b7e0436eaa018d7b002ad8070965a117888cb953e4a0e9d36eb36`.

| Назначение | Путь / идентификатор |

| Model ID | `wardrobe-15-katania-four-door` |

База Ш × В × Г — **1600 × 1900 × 400 мм**. Диапазоны 1600–2400 / 1900–2700 / 400–600 мм, шаг 1 мм. В runtime единицы — метры, UI `displayUnit: 'mm'`.

Корпус 16 мм, фасады 18 мм, задник 4 мм; эти толщины оценены по фото и фиксированы. Цоколь 80 мм, перекрытие фасадом 30 мм — из карточки. Общая глубина включает выступ ручек 28 мм.

## Единственное необходимое подключение в общем коде

В актуальном `src/configurator/furnitureRegistry.ts` добавить импорт:

```ts
import { catalogue as wardrobe15 } from '../three/models/wardrobe-katania-four-door/catalog'
```

И элемент существующего `Map`:

```ts
[wardrobe15.id, wardrobe15],
```

Использовать **catalogue**: `catalog.ts` оставляет resize rules и target-массивы вне начального бандла; `loadRuntime()` лениво получает полный конфиг. Не импортировать тяжёлый `config.ts` непосредственно в registry.

В этом snapshot уже есть все необходимые механизмы: категории мебели, `textureTransforms`, слоты материалов, вид наполнения, `articulations` и сохранение позы через `motion.withClosedPose`. Обновлять FurnitureController, App, состояние конструктора или materialRegistry для данного наполнения не требуется. Общих изменённых файлов в ZIP нет.

Модель использует существующие покрытия. Корпус/полки, фасады и ручки выбираются независимо; механизмы остаются фиксированными. Изображения древесины берутся из текущего общего каталога проекта. Новые копии этих файлов не добавлять.

## Конструктивное решение, которое важно сохранить

Четыре равных отделения имеют по верхней полке и **торцевому кронштейну во всём диапазоне глубины 400–600 мм**. В карточке товара от 500 мм показана поперечная штанга. Автозамена наполнения и выдвижение кронштейна здесь не реализованы; это отдельная будущая задача общего механизма вариантов. Сохранить описание модели без обещания такой автоматики.

Четыре двери открываются на −105°, −105°, +105°, +105° вокруг задней петлевой кромки. Ручки и подвижная часть петель являются потомками соответствующей двери. При скрытии фасадов скрывается группа целиком. Геометрия дверей содержит по 48 канавок; ширина 3 мм и глубина 1,8 мм постоянны, растут только плоские промежутки. Количество канавок и размеры фурнитуры — визуальные оценки.

## Порядок интеграции

1. На актуальной принятой версии создать отдельную ветку. Проверить содержимое ZIP по manifest и SHA-256; проверить отсутствие конфликта Model ID и новых путей. Локальный baseline-коммит model-чата не является коммитом вашего репозитория.
2. Импортировать только перечисленные model-specific файлы с относительными путями от корня проекта. Существующие общие файлы сохранить; root manifest пакета при необходимости перенести в папку этой модели, чтобы не заменить manifest другой задачи.
3. Добавить две записи registry выше и проверить ленивую загрузку модели. Стартовую модель проекта менять не требуется.
4. Запустить общие проверки, затем открыть шкаф в реальной сцене конструктора. Проверить base / 2000×2300×500 / max / возврат, шаг 1 мм, все три группы материалов, дерево на торцах, четыре двери, вид наполнения, изменение размеров при открытых дверях и переключение на другие модели и обратно.
5. Выполнить Blender-проверку командой ниже на компьютере с Blender 4.x; проверить сохранённую и реимпортированную сцену. CPU-превью из пакета не заменяют эти два визуальных этапа.
6. После проверки включить все model-specific файлы и registry в отдельный коммит; вернуть пользователю проверенный интеграционный ZIP с относительными путями и точными командами коммита по принятому процессу проекта.

```sh
npm ci
npm test
npm run build
```

Для воспроизведения проверок модели и glTF:

```sh
npm ci --prefix assets/source/wardrobe-15-katania-four-door
node assets/source/wardrobe-15-katania-four-door/validate_model.mjs
npm test -- src/three/models/wardrobe-katania-four-door/wardrobe.test.ts
blender --background --python assets/source/wardrobe-15-katania-four-door/create_model.py
```

В этой среде существующие тесты `tabletopEdgeProfile.test.ts` иногда превышали стандартный лимит 5 секунд уже на исходном проекте. Отчёт содержит исходные результаты и отдельный полный прогон с ограничением числа workers и увеличенным лимитом времени, без изменений исходников общих тестов. Использовать точные результаты из `validation-report.md`, не представлять исходный `npm test` как безусловно зелёный.

Пример отдельного коммита после успешной интеграции и проверки путей:

В текущем `.gitignore` папка `docs/updates/` исключена. Поэтому для единственного нового handoff-файла ниже применяется отдельный `git add -f`.

```sh
git add public/models/wardrobe-15-katania-four-door.glb src/three/models/wardrobe-katania-four-door assets/source/wardrobe-15-katania-four-door src/configurator/furnitureRegistry.ts

```
