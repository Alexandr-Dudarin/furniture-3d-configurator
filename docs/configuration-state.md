# Состояние и сохранение конфигуратора — v2

Состояние хранит выбранную модель и отдельные размеры/материалы каждой
зарегистрированной модели. Категория мебели в логике сохранения не используется.
Новые модели получают начальные значения из своего `FurnitureDefinition`.

## Поведение

- Переключение моделей сохраняет их индивидуальные настройки.
- При обычном открытии страницы восстанавливается последнее локальное состояние.
- При открытии ссылки её параметры заменяют настройки только указанной модели
  и делают её выбранной. Настройки других моделей сохраняются.
- В отсутствующих полях ссылки используются начальные значения модели, а не
  личные настройки получателя: одна ссылка должна давать одинаковый результат.
- Сброс применяется к выбранной модели. Её начальные размеры и материалы берутся
  из конфигурации модели; настройки остальных моделей остаются прежними.
- Модульная сборка хранится отдельно в `assembly`; переключение режимов сохраняет
  настройки обеих частей. Сброс сборки не сбрасывает готовые модели и наоборот.
- Камера, освещение, состояния раскрытия списков и история изменений не сохраняются.

## Локальное состояние

Ключ localStorage: `furniture-3d-configurator:configuration:v2`.
Если он отсутствует, читается прежний ключ `furniture-3d-configurator:configuration:v1`.
Его данные мигрируют при загрузке и записываются в v2; исходный ключ v1 не удаляется.
Сохранения v1 сохраняют все допустимые размеры и покрытия готовых моделей.
Новые поля получают defaults: mode=catalog, assembly=начальная сборка.

```ts
type ConfiguratorSession = {
  version: 2
  mode: 'catalog' | 'builder'
  assembly: TableAssemblyConfiguration
  selectedModelId: string
  models: Record<string, {
    dimensions: Record<string, number>
    materials: Record<string, string>
  }>
}
```

Размеры записываются в метрах. Имена размеров и material slots берутся из
контракта конкретной модели. Автосохранение выполняется через 250 мс после
последнего изменения; событие `pagehide` и размонтирование выполняют немедленную
запись. Создание ссылки всегда использует актуальное состояние без ожидания записи.

При запрете localStorage или исчерпании квоты редактор работает в памяти и
показывает, что автосохранение недоступно. Можно сохранить ссылку вручную.
Повреждённый JSON и неподдерживаемая версия локального формата заменяются
начальными настройками с уведомлением. Удалённые модели и неизвестные поля
игнорируются, новые модели получают defaults. Невалидные отдельные значения
заменяются допустимыми по правилам ниже.

Хранилище привязано к origin: `localhost` и `127.0.0.1`, разные порты, HTTP и
HTTPS имеют отдельные сохранения. Между вкладками нет синхронизации в реальном
времени; последняя записавшая вкладка определяет состояние следующего открытия.
Это локальное сохранение последнего состояния, не серверная библиотека проектов.

## Ссылка

Готовые модели продолжают использовать формат ссылки v1 для совместимости.
Модульные сборки используют v2 с `kind: "table-assembly"` и полем `assembly`.
Полная схема модулей приведена в [контракте модулей](table-module-standard-v1.md).
Парсер принимает оба формата. Ссылка сборки открывает режим builder, ссылка
готовой модели — режим catalog. Остальные локальные настройки сохраняются.

Query-параметр `config` содержит JSON, закодированный через `URLSearchParams`:

```json
{
  "version": 1,
  "modelId": "table-05-round-fluted-pedestal",
  "dimensions": { "diameter": 1.3 },
  "materials": {
    "primaryTop": "marble-black-gold",
    "frameMetal": "metal-white-matte"
  }
}
```

Ссылка включает только выбранную модель или активную модульную сборку. Путь приложения, hash и остальные
query-параметры сохраняются. Текстуры, GLB и локальные настройки других моделей
не включаются. Получателю нужна та же доступная версия каталога приложения.

Если страницу открыли по ссылке и затем изменили параметры, `replaceState`
обновляет текущую ссылку вместе с автосохранением. Перезагрузка поэтому не
возвращает устаревшие параметры исходной ссылки. Новые записи в истории браузера
при движении ползунка не создаются. При обычном входе без `config` URL остаётся
без параметров конфигурации; кнопка копирования формирует ссылку отдельно.

## Валидация

Для готовых моделей источником разрешённых значений служит `FurnitureDefinition`.
Для сборок — каталог форм/оснований и `normalizeTableAssembly`: проверяются IDs,
совместимость формы и основания, размеры, толщина, высота и покрытия. Исправление
параметров ссылки сопровождается уведомлением.

Правила готовых моделей:

- неизвестная модель, неизвестная версия, повреждённый/слишком длинный JSON или
  дублированный `config` отклоняются; открывается сохранённое либо начальное состояние;
- отсутствующие и нечисловые размеры заменяются `base`;
- числовые размеры ограничиваются `min/max` и округляются к `step` от `min`;
- значения NaN и Infinity не допускаются;
- покрытия допускаются только из `allowedFinishes` конкретного слота;
- недоступное покрытие заменяется `defaultFinish`;
- неизвестные размеры, слоты и прочие поля не попадают в рабочее состояние.

Отклонённая ссылка удаляется из адреса, остальные параметры URL сохраняются.
Частично исправленная ссылка открывается с уведомлением об изменённых значениях.
Следующее автосохранение записывает нормализованное состояние. Новый формат
должен иметь новую версию и явные правила миграции.

## Проверки

`savedConfiguration.test.ts` проверяет все зарегистрированные модели,
переключение/сериализацию/ссылки, сброс, валидацию и произвольные размеры будущих
категорий мебели. `configuratorStore.test.ts` проверяет приоритет ссылки,
перезагрузку, debounce, `pagehide`, ошибки хранилища и повторное подключение
React StrictMode. Геометрия и UV остаются под существующими GLB integration-тестами.

Модульные тесты дополнительно проверяют миграцию v1 → v2, сохранение сборки,
ссылки v2, независимый сброс режимов и нормализацию несовместимых модулей.

### Совместимость с modular-tables-v2

Формат сохранений/ссылок остаётся v2. Новый ID основания — `four-legs`.
Его высота ограничена 0.61–0.81 м, а формы — четырьмя прямоугольными вариантами.
У `ellipse` и `capsule` ширина ограничена длиной минус 0.2 м. Это правило
также применяется к старому localStorage и ссылкам; изменённая ссылка получает
статус `adjusted`. Например, 1.1 × 1.1 м восстанавливается как 1.1 × 0.9 м.
Для точного открытия новых сборок приложение получателя также должно быть обновлено.
