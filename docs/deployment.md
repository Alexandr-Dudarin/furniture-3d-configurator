# Развёртывание и автоматические проверки

Актуально для публичного проекта на 2 октября 2026 года.

- Репозиторий: [Alexandr-Dudarin/furniture-3d-configurator](https://github.com/Alexandr-Dudarin/furniture-3d-configurator).
- Демо: [furniture-3d-configurator-kappa.vercel.app](https://furniture-3d-configurator-kappa.vercel.app/).
- Production-ветка: `main`.

## Локальные проверки

Используйте Node.js 24 и корень проекта с `package.json`:

```bash
npm ci
npm run lint
npm test -- --testTimeout=60000 --maxWorkers=2
npm run build
npm run check:publication
```

`npm ci` использует версии из lockfile. Два workers сдерживают расход памяти
при проверках крупных GLB; тайм-аут 60 секунд относится к отдельному тесту.
Два теста необязательного локального архивного GLB в чистом checkout
пропускаются. Остальные тесты выполняются.

`prebuild` проверяет входные ресурсы и состав загрузки. После сборки
`check:publication` проверяет `dist/` и побайтовое совпадение его ресурсов
с `public/`. Размеры пересчитываются при каждом запуске.

## GitHub Actions

Workflow [ci.yml](../.github/workflows/ci.yml) запускается при push в `main`,
для pull request в `main` и вручную из вкладки Actions. Выполняются
установка, ESLint, тесты, сборка и проверка публикационных ресурсов.

- Runner: Ubuntu, Node.js 24, кэш npm по `package-lock.json`.
- Старый запуск для того же PR или ветки отменяется при новом коммите.
- Права — только чтение репозитория. Ключи API и Vercel не нужны.
  GitHub Actions здесь ничего не развёртывает и не коммитит.
- Actions закреплены полными SHA; при обновлении сверяются официальные релизы.
- Ошибки не скрываются через `continue-on-error`; логи доступны в Actions.

Workflow сам по себе **не запрещает** слияние при ошибках. Для обязательной
проверки нужно отдельно настроить защиту `main` в GitHub и выбрать проверку
`Quality checks`. Эти настройки не включаются автоматически файлом workflow.

## GitHub → Vercel

| Настройка | Значение |
| --- | --- |
| Framework Preset | Vite |
| Root Directory | Корень репозитория |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | 24.x для соответствия локальным проверкам и CI |
| Environment Variables | Не требуются |

После слияния в `main` подключённый проект Vercel создаёт production deployment.
Pull request может получить отдельное preview-развёртывание через интеграцию
Vercel; это не шаг GitHub Actions. Текущее значение Node.js проверяется
в настройках Vercel — workflow не меняет его автоматически.

`.vercelignore` задаёт список разрешённых входных файлов. Сам этот файл нужен
`prebuild` и также включён в список. Исходники ассетов, документация и локальные
архивы не нужны готовому сайту. `.gitignore` управляет добавлением в Git,
`.vercelignore` — составом загрузки Vercel CLI. Уже отслеживаемый файл
не исчезает из Git от одной записи в `.gitignore`.

`vercel.json` поддерживает корневые ссылки с `?config=...` и старые маршруты
`/feedback/...`, `/catalog/...`, `/viewer/...`. Отсутствующие GLB и текстуры
не переписываются на HTML.

## Проверка опубликованной версии

1. Открыть основной адрес без входа в Vercel, например в режиме инкогнито.
2. Переключить модели каталога, изменить размер и материал.
3. Собрать стол и гардеробную, проверить двери, ящики и материалы секций.
4. Открыть скопированную ссылку в новой вкладке и обновить её.
5. Сохранить PNG и проверить ракурс и положение открытых деталей.
6. Проверить узкий экран и работу на физических ноутбуке и телефоне.

LocalStorage привязан к адресу сайта. Для переноса локального варианта
используйте конфигурационную ссылку, заменив только адрес сайта и сохранив
параметр `config`. Камера и текущее открывание в ссылку не входят.
