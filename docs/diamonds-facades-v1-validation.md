# Проверка фасадов «Ромбы» v1 — ревизия 1.1

База — принятая «Ёлочка», коммит пользователя `794be68`.

## Автоматические проверки

- `npm run test -- --testTimeout=30000 --maxWorkers=2` — **49 файлов, 427 тестов прошли**.
- `npm run build` — успешно. SceneView: 679,10 kB / gzip 176,81 kB.
  Прежнее предупреждение о чанке больше 500 kB сохраняется.
- ESLint изменённых в ревизии `diamondsGeometry.ts`, `facadeController.ts`,
  `facadeController.test.ts` — без ошибок. Остальные файлы этапа прошли ESLint
  в первой ревизии.
- Лучами проверены глубина пересечений и обоих направлений канавок,
  V-склоны, плоские участки и метрические UV. На пересечении нет второго
  слоя и дополнительной глубины. Проверены изменения ширины на 1 мм.
- Геометрия всех девяти моделей проверена на предельных и асимметричных
  размерах: замкнутость, положительный объём, согласованный обход,
  отсутствие вырожденных треугольников, физический габарит.
- Регрессионные случаи «Норда» и «Марвэла» на доле диапазона 0,37
  проходят после замены поиска стыков. Полные ромбы, обрезанные участки
  и монтажные поля проверяются теми же тестами замкнутости.
- Три новые проверки повторного использования геометрии: одна сборка
  для одинаковых дверей (включая погрешности исходных координат «Катании»),
  разные толщины/монтажные полосы/рамки не смешиваются, замена и выгрузка
  освобождают общий ресурс один раз. Ошибка в середине сборки освобождает
  новые ресурсы и сохраняет прежний набор.
- Общие тесты контроллера включают `diamonds`: min/base/max, открывание,
  привязки ручек, смена покрытия, возврат к исходному виду и освобождение
  геометрии. Сохранения, ссылки, сброс и прежние значения проверены тестами.

## Границы проверки

Визуальную проверку этого обновления в браузере выполнить не удалось:
доступный проверочный браузер отказался открывать локальный сервер
(`ERR_BLOCKED_BY_CLIENT`). Скриншотов «Ромбов» из приложения здесь нет.
Прохождение автоматических тестов не заменяет эту проверку.

На компьютере пользователя перед общим коммитом «Ромбов»:

0. Непрерывно менять ширину/высоту у «Катании», «Челси», шкафа с
   центральными ящиками и белого комода; повторить при открытых дверях.
   Сравнить отзывчивость с первым пакетом, проверить итог после отпускания.

1. На белом комоде и «Челси» выбрать «Ромбы», проверить белое и цветное
   покрытие при неподвижной камере и после поворота.
2. У «Бруклина» посмотреть низкие ящики на минимальной высоте, увеличить
   ширину и вернуть исходные размеры. У «Катании» проверить максимальную
   высоту и ширину. У «Байкала» — гладкое поле под ручками.
3. Открыть/закрыть двери и ящики; у шкафов включить «Наполнение» и вернуть
   внешний вид. Проверить «Исходный» у декоративных моделей и сброс.
4. Выбрать древесный материал, сохранить PNG и ссылку, открыть ссылку
   в новой вкладке. Рисунок должен восстановиться.
5. Проверить доступность карточки на телефоне и читаемость рельефа.

Физический телефон, FPS и нагрев не проверялись. Муар при движении —
известная отдельная задача; новое сглаживание этим этапом не добавлялось.

## Измерение CPU-пересчёта

Сравнение первой версии пакета и ревизии 1.1 в одной среде Node/Vitest,
один worker, без параллельных тестов во время замеров. Измерен вызов
`facadeController.update(..., 'diamonds')` для всех фасадов модели.

Начальные размеры — максимальные; 28 последовательных изменений ширины
с шагом 1 мм, затем 28 изменений высоты. Первые 8 вызовов каждой серии —
прогрев, ниже медиана оставшихся 20. Группы панелей созданы без GLB:
в измерение не входят корпус, React, GPU, тени и сглаживание кадра.

| Модель / изменение | Первая версия, мс | Ревизия 1.1, мс |
| --- | ---: | ---: |
| Челси / ширина | 93,1 | 9,8 |
| Челси / высота | 85,3 | 6,3 |
| Катания / ширина | 239,9 | 7,8 |
| Катания / высота | 233,0 | 6,2 |
| Шкаф с центральными ящиками / ширина | 216,1 | 14,2 |
| Шкаф с центральными ящиками / высота | 195,0 | 14,2 |
| Белый комод / ширина | 42,7 | 1,6 |
| Белый комод / высота | 41,5 | 1,5 |

Это измерение устранённой CPU-задержки, не FPS и не гарантия частоты кадров
на ноутбуке/телефоне. Ревизия не откладывает расчёт до отпускания ползунка
и не заменяет рельеф плоским изображением во время движения.

Штатный тест геометрии подтверждает лимит менее 12 000 треугольников
на отдельную панель «Ромбы» при проверенных размерах всех девяти моделей.

## Установка

Архив содержит весь этап поверх принятой базы, включая исправление
рывков. Его можно наложить поверх уже применённой незакоммиченной
первой версии «Ромбов». Проверка файлов:
`node scripts/check-diamonds-facades-v1.cjs`, ожидаемый маркер —
`DIAMONDS_FACADES_V1_FILES_CONFIRMED`.
Команды отдельного коммита — `docs/updates/diamonds-facades-v1.md`.
