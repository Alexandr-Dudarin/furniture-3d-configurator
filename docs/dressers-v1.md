21 сентября 2026. Основа — принятый пользователем режим наполнения шкафов.
Использован модельный пакет комодов v2; его пять GLB перенесены без изменений.

| «Байкал», 14 | 402 × 1030 × 331 | 350–600 / 900–1200 / 300–500 | 5 / 0 / 0 |

Шаг — 1 мм; ввод и ползунки используют миллиметры, внутренняя геометрия —
метры. Толщина основных панелей 16 мм, задней стенки 4 мм, дна ящика 6 мм;
сохраняются зазоры, размеры ручек, сечения декора и положение на полу.
Количество ящиков и полок фиксировано. Диапазоны — ограничения визуальной
модели, а не подтверждённые производственные опции.

## Материалы

Корпус с внутренними деталями, фасады и наружные ручки меняются отдельно.
Петли, направляющие и подпятники сохраняют исходные материалы. Модель 10
не имеет наружных ручек, поэтому соответствующего выбора в UI нет.

Добавлены восемь процедурных отделок плит с исходными оттенками и шероховатостью,
а также сатиновая латунь. «Норд» начинает с кашемира и латунной ручки,
«Бруклин» — с белого глянца, «Марвэл» и «Байкал» — с дубового корпуса и белых
фасадов. Различия близких белых оттенков сохранены. Глянец задаётся roughness
0.14; плиты неметаллические. «Белый Марвэл» — цвет, отдельная брашированная
текстура не заявляется; рифление фасада выполнено геометрией.

Для всех комодов доступны четыре ранее существовавших дубовых покрытия,
матовый белый, серый, графит и кашемир. Глянцевый белый доступен для фасадов.
Каждая модель также сохраняет собственный исходный оттенок. Орех с другой
ориентацией волокон в этот список не добавлен.

GLB 13/14 используют существующие `public/materials/wood/oak-natural/`.
Копий JPG и новых изображений для однотонных цветов нет. Все исходные карты
сохранили разрешение 2048 × 2048 и контрольные суммы.

Общее необязательное поле `materialSlots.<slot>.finishOverrides` позволяет
задать `normalScale` для конкретного покрытия на детали. Для дубового корпуса
13/14 это 0.2, как в авторском GLB; общий `oak-natural` остаётся 0.65 для
прежних моделей. Параметр применяется только к собственному материалу слота,
не меняет registry или общий источник изображения, восстанавливается при reset.
Названия «дуб» и «кашемир» обозначают цифровые приближения: точное соответствие
конкретному образцу производителя требует сопоставления с этим образцом.

## UV, загрузка и сохранения

Использован существующий общий affine UV runtime. Типизированные привязки
генерируются из `model-contract.json`: полезные длины сегментов, движение
кромок и фаза рисунка учитываются раздельно. Проверка по вершинам настоящих
GLB охватывает панели, торцы, рифление и угловой декор при min/mid/max/return
и смене покрытия. Допуск — менее 0.000001 UV-единицы.

Лёгкий `catalog.ts` нужен интерфейсу; `runtime.ts`, resize rules и UV загружаются
по выбору модели. GLB и PBR также запрашиваются по требованию. Камера учитывает
максимальный габарит; изменение размеров и покрытий не сбрасывает ракурс.
Размеры, покрытия, ссылка и сброс работают через прежний общий формат сохранений.
Сохранённые столы, сборки и шкафы не требуют миграции.

Комоды показываются закрытыми. Подготовленные группы дверей и ящиков сохранены
для следующего этапа с интерактивным открыванием. Переключатель наполнения
прежних шкафов продолжает работать.

## Воспроизведение

Авторские исходники, референсы, паспорта и отчёты сохранены в
`assets/source/dresser-*`; передача исходного пакета — в
`assets/source/dressers-integration/DRESSERS_10_14_INTEGRATION.md`.
Авторские отчёты описывают модельный пакет до production-интеграции:
статус legacy UV-пробы не является результатом нового runtime.

После пересборки модели её авторским генератором выполнить:

```bash
python assets/source/dressers-integration/generate_runtime.py
python assets/source/dressers-10-14-shared/check_resources.py --strict
npm test
npm run build
```

Генератор production-обвязки не изменяет авторские `config.ts` и GLB.
Корневые npm-зависимости не добавлены. Текущие результаты интеграционных
проверок находятся в `assets/source/dressers-integration/validation-report.md`.

## Обновление catalog panels v1 (22 сентября 2026)

Для «Бруклина» начальное покрытие ручек в production-каталоге изменено на
`metal-brass-satin` («Латунь сатиновая»). Источник этого значения —
`assets/source/dressers-integration/generate_runtime.py`; runtime получает
настройку из сгенерированного `catalog.ts`. Авторский review-конфиг и GLB
остаются исходными, как и для остальных production-переопределений покрытий.
Сохранённый белый или любой другой допустимый выбор не заменяется автоматически.
Новая сессия и сброс модели используют латунь.
