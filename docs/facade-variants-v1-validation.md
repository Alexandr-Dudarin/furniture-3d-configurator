# Проверка facade-variants-v1

22 сентября 2026. Основа — принятый `catalog-scale-v1`.

## Автоматические проверки

- `npm test -- --maxWorkers=1 --testTimeout=15000`: **357 тестов, 45 файлов, PASS**.
- `npm run build`: PASS. Прежнее предупреждение Vite о размере отложенного
  3D chunk сохраняется; порог не повышался.
- ESLint 23 изменённых TS/TSX: PASS.
- Общий `npm run lint`: 11 прежних ошибок в не изменённых файлах:
  10 `no-explicit-any` в двух `export_preview_states.ts` столов 05/06;
  одна `set-state-in-effect` в `CustomSelect.tsx`. Эти файлы совпадают с базой.
- Новый GLB «Катании»: glTF Validator — 0 errors, 0 warnings, 0 infos, 0 hints.

Новые проверки покрывают:

- min/base/max реальных GLB «Челси» и «Бруклин» для трёх рисунков;
- неизменную толщину и заднюю монтажную плоскость, принадлежность подвижной
  сборке, сохранение промежуточной позы, возврат к исходным панелям;
- замкнутость геометрии по рёбрам, ненулевую площадь треугольников,
  единичные нормали, конечные UV и плоские нормали рамки/центрального поля;
- постоянные шаг, ширину и глубину профиля, добавление симметричных пар,
  метрические UV вдоль канавок и освобождение заменяемой геометрии;
- независимость покрытий, скрытие новых дверей в наполнении;
- сохранение/ссылки/reset, старые v1/v2 и миграцию ключа v2 в v3;
- сохранение прежней глубины 400 мм и новый сброс «Катании» на 450 мм.

## Проверка браузера

Локальная production-сборка, Chromium с программным WebGL. Доступ к состоянию
добавлялся только во временную QA-сборку и в архив обновления не входит.

Проверены выбор всех рисунков кнопками интерфейса, реальное нажатие на новые
фасады в 3D, смена рисунка с открытой дверью/ящиком, открывание всех частей,
зелёное и бежевое покрытия, древесина и латунные ручки. Изменение размеров
«Бруклина» от 1200 × 550 до 2000 × 900 мм сохраняет профиль. Фасады, сводка
и материалы восстановлены после reload и перехода по ссылке; reset возвращает
исходные гладкие панели.

PNG скачан через интерфейс. Проверены финальные кадры «Челси» с рамкой,
«Бруклина» с рамкой и открытого рифлёного «Бруклина». Экспорт сохраняет
камеру и состояние ящиков. После правки нормалей отдельно просмотрены рамки
с зелёным покрытием и древесиной: широкого ложного скоса больше нет.

При ширине viewport 390 и 320 px выбор рисунка работает, карточки и подписи
помещаются без горизонтального переполнения. Это эмуляция размеров экрана,
а не измерение FPS на физическом смартфоне. Ошибок страницы, console.error
и HTTP >= 400 в проверенных сценариях нет.

У «Катании» после 400 мм → «Сбросить эту модель» проверены одновременно
состояние приложения и bounding box геометрии: глубина **450 мм**.

## Геометрический бюджет профилей

Число треугольников ниже относится к одной новой панели, без корпуса,
ручек, ящика и проходов теней. Гладкий стиль использует исходные панели.

| Модель | Канавок min/base/max | Треугольников рифления min/base/max | Рамка, треугольников |
|---|---|---|---|
| Челси, одна дверь | 13 / 17 / 23 | 3426 / 4434 / 5946 | 80 |
| Бруклин, один ящик | 27 / 37 / 47 | 6954 / 9474 / 11994 | 80 |

Новых mesh: 2 у шкафа, 6 у комода. У максимального «Бруклина» новые
рифлёные панели вместе имеют 71 964 треугольника.

После прогрева и восьми циклов рамка → рифление у максимального «Бруклина»
`renderer.info.memory` не вырос: **925 geometries / 4 textures** до и после.
Это счётчик ресурсов всей сцены, включая уже загруженные исходные панели,
а не только новых фасадов. Он не является измерением общего потребления RAM.

## Ограничения

Проверка физического мобильного устройства, FPS и Blender для процедурных
вариантов не выполнялась. Мелкие канавки на удалённом ракурсе могут требовать
дальнейшей работы со сглаживанием после проверки на целевых устройствах.
Исходные PBR и прежняя геометрия гладких пилотных моделей не уменьшались.
Реалистичность конкретного материала оценивается по реальному образцу.
Проверки здесь подтверждают работу визуального конструктора, не заводскую
технологичность выбранного профиля.
