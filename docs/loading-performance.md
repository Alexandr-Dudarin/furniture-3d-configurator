# Загрузка конфигуратора и качество материалов

Этап loading v1, 21 сентября 2026 года. Основа — принятая studio scene v1.

## Что изменилось

Интерфейс и сохранённая конфигурация доступны до загрузки Three.js. После
первого отображения интерфейса `FurnitureViewer` динамически импортирует
`SceneView`. Сцена создаётся один раз; смена модели, размеров или материалов
не перезапускает камеру, свет и окружение. Самостоятельные GLB загружаются
только при выборе соответствующей модели/основания.

`ShapePreview` и построитель геометрии используют общий контур без зависимости
от Three.js. Карточки металла используют явно заданный цвет sRGB. Поэтому
3D-библиотека не попадает обратно в начальный JavaScript через интерфейс.

Во время загрузки показано состояние ожидания. Если не загрузился GLB или
материал, кнопка повторяет подготовку текущей модели. Если не загрузился сам
модуль 3D, кнопка перезагружает страницу с текущей конфигурацией в URL:
некоторые браузеры сохраняют ошибку динамического импорта до новой навигации.
Это сохраняет выбор даже при недоступном localStorage. Ошибка запуска сцены
имеет отдельный повтор без сброса панели.

## Превью и исходные материалы

Для карточек используются отдельные WebP до 192 × 192 пикселей. Все 13 файлов
занимают 73 532 байта, исходные цветовые карты — 19 414 457 байт. Это уменьшает
набор изображений карточек приблизительно на 99,6%. `loading="lazy"` сохранён.

На мебели по-прежнему применяются исходные карты 2048 × 2048: цвет, roughness
и normal. UV, масштаб рисунка, параметры материалов, анизотропная фильтрация,
освещение, тональное отображение и качество теней не изменялись. Превью не
подставляются на модель даже временно. Существующие GLB не изменены.

Превью строятся из соответствующего base-color без изменения оттенка; ICC
профиль исходника сохраняется (есть у натурального ореха и ясеня). Воспроизведение:

```powershell
python assets/materials/source/generate_material_previews.py
```

Нужен Pillow, как и для существующих Python-генераторов материалов. Для
пользователя приложения Python не требуется: готовые превью включены в проект.
Новая текстурная отделка задаёт `previewUrl`; однотонная — `previewColor`.

**Продуктовое требование:** материал должен быть узнаваемым и близким к
реальному образцу по цвету, масштабу рисунка, блеску и рельефу. Сохранность
текущего изображения не доказывает физическую точность каждого материала.
Дальнейшая калибровка требует референсов конкретных покрытий и достоверных PBR
карт. Существующие процедурные варианты мрамора остаются визуальными
вариантами, а не обещанием совпадения с конкретным каменным слэбом.

## Кэши и владение ресурсами

- GLB: до 4 завершённых источников и до 24 MiB исходных байтов. Повторный выбор
  недавно использованной модели не требует новой загрузки. GLTFLoader каждый
  раз создаёт независимую геометрию и материалы; размеры одного экземпляра
  и освобождение его ресурсов не затрагивают другой.
- Текстуры: до 12 завершённых шаблонов и до 96 MiB оценочного объёма
  декодированных изображений (`width × height × 4`). Для текущих карт 2048²
  это 6 карт, то есть два набора по три. Материалы получают отдельные Texture
  с прежними настройками; изображения могут быть общими.
- Вытесняются давно не используемые завершённые записи. Одновременные запросы
  одного источника объединяются. Ошибки не остаются в кэше; повреждённый GLB
  исключается после ошибки разбора.
- Удаление модели освобождает её GPU-ресурсы и принадлежащие загрузке GLB
  ImageBitmap, даже если встроенный материал был заменён выбранным покрытием.
  Bitmap другого экземпляра и картинки активных текстурных клонов не закрываются.
- После удаления просмотрщика оба кэша очищаются. Поздние завершения очищенных
  запросов не восстанавливают старые записи, поздняя ошибка не удаляет новую.
  Остановленный контроллер материала не начинает загрузку следующих частей.

Это бюджеты **повторно используемых источников**, а не предел памяти всего
браузера. Активная мебель, GPU, незавершённые загрузки и HTTP-кэш учитываются
отдельно. Вытеснённый материал при новом выборе может потребовать повторной
загрузки; браузер при этом может использовать HTTP-кэш.

## Результаты

Обычная production-сборка, без диагностических вставок; десятичные kB:

| Показатель | Studio scene v1 | Loading v1 |
| --- | ---: | ---: |
| Начальный JavaScript | 878,48 kB | 239,61 kB |
| Начальный JavaScript gzip | 235,56 kB | 73,28 kB |
| Отдельный модуль 3D | — | 644,44 kB |
| Отдельный модуль 3D gzip | — | 163,99 kB |
| Все 13 изображений для карточек | 19,41 MB | 73,53 kB |

Общий JavaScript после запуска 3D составляет около 884 kB. Выигрыш — ранняя
доступность интерфейса и отсутствие полноразмерных карт ради превью; это не
обещание уменьшить библиотеку Three.js или ускорить отрисовку на любом GPU.
Предупреждение Vite о модуле более 500 kB остаётся для отложенного 3D-модуля;
порог предупреждения не повышался.

В Chromium на чистом открытии каталога запрошена 1 полноразмерная цветовая
карта выбранной отделки вместо 13 уникальных цветовых карт ради карточек.
В сборщике с закрытыми материалами и прежде загружалось только выбранное
покрытие; основная экономия там возникает при раскрытии карточек материалов.

Проверки и ограничения замеров: [validation-report](../assets/source/loading/validation-report.md).
Рендер по запросу, новый DPR, сжатие исходных PBR и переделка GLB в этот этап
не входят. Загрузку кода будущих шкафов/комодов стоит отделять, когда появится
их собственная тяжёлая логика; небольшие каталоги метаданных остаются общими.
