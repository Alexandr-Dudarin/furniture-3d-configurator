# Проверки relief-filter-v1

Дата: 27.09.2026. Среда: Linux, Node 24.19, Three.js из lockfile проекта.

## Автоматические проверки

- Полная серия Vitest: **53 файла, 474 теста**, 43,55 с; maxWorkers=2,
  testTimeout=60000. Включая реальный GLB «Катании», переключение дерево/
  однотонный материал, объединение сеток, изменения размеров, открывание.
- После завершающих защитных правок: профильные тесты фильтра и PNG —
  **26/26**. Проверены неизменность UV/CPU-геометрии, границы толщины,
  тыльная плоскость/фаска, метрическая ширина при scale и повторное
  использование атрибутов без пересборки при вращении.
- PNG: новая серия 16 образцов одной позы при движении и частичном накоплении;
  следующий кадр движения сбрасывает сумму. Проверены завершённое состояние,
  восстановление view/projection, отказ/повтор после ошибки, предел памяти,
  отсутствие float-буфера, выключенное уточнение и disposed runtime.
- TypeScript + Vite production build: успешно. SceneView около 693 kB,
  около 181 kB gzip. Предупреждение >500 kB остаётся; лимит не скрывали.
- ESLint изменённых TS/TSX файлов: успешно. Это не утверждение о полном
  историческом lint всего репозитория.
- Новых npm-зависимостей и изменений GLB нет.

## Программная графическая проверка

Доступен Mesa llvmpipe (LLVM 20.1.2), OpenGL 4.5. Скомпилированы полные
вершинные шаблоны установленного Three Standard / Depth / Distance с
новой вставкой и раскрытыми ShaderChunk; без текстурных/light defines.
Отдельно отрисован исходный профиль одной двери «Катании» (5220 вершин
развёрнутых треугольников) с тем же алгоритмом фильтра и простым Lambert
освещением. Это **не полный WebGL viewer и не проверка браузера пользователя**.

512×512, FOV 35°, 61 поза от −15° до +15°, дистанция 3 м, один образец.
Внутренняя полоса изображения исключает силуэт. Для этого теста:

| Измерение (8-битные значения) | Без фильтра | С фильтром |
| --- | ---: | ---: |
| RMS изменения пикселей между позами | 17,76 | 0,95 |
| Среднее пространственное отклонение полосы | 33,82 | 0,40 |
| Средняя яркость полосы | 163,19 | 171,25 |

Последняя строка показывает ограничение: ослабление рельефа приближённое,
среднее освещение не интегрируется физически точно. Переход плавный, но
его видимость нужно проверить с настоящими покрытиями и окружением.

На близком фронтальном ракурсе с дистанции 0,75 м получено побитовое
совпадение изображений с фильтром/без него (максимальная ошибка 0).
Эти цифры подтверждают работу алгоритма в описанном тесте, но не являются
обещанием такого же процента уменьшения муара или FPS в приложении.

## Что ещё требует приёмки

Полная браузерная сцена, реальный GPU ноутбука, Windows/ANGLE, телефон,
текстуры и отражения с текущим окружением, мягкие тени и скорость экспорта
на этих устройствах здесь не проверены. Доступного браузера для этой
проверки в среде нет. Нельзя считать муар полностью устранённым до
визуальной проверки движения. Порядок приёмки — в relief-filter-v1.md.
