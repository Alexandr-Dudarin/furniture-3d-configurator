# Осмотр наполнения шкафов — v1

21 сентября 2026. Основа: принятая пользователем интеграция трёх шкафов
и исправление цельной задней стенки «Челси».

## Возможности

В каталоге шкафов добавлен переключатель **«Внешний вид / Наполнение»**.
Внешний вид показывает закрытые двери. Наполнение скрывает дверные сборки
вместе с их ручками и подвижной фурнитурой. Корпус, задняя стенка, полки,
штанги, ящики и фурнитура на корпусе остаются видимыми.

| Модель | Полки | Штанги | Ящики |
|---|---:|---:|---:|
| Шкаф с центральными ящиками, 07 | 4 | 2 по бокам | 3 в центре |
| Четырёхдверный шкаф, 08 | 9 | 1 в центре | — |
| Двухдверный «Челси», 09 | 2 | 1 | — |

Все эти внутренние детали уже присутствуют в исходных GLB. В этом этапе
геометрия моделей не менялась; второй GLB для внутреннего вида не создавался.
Ящики 07 остаются собранными и закрытыми, их фасады не скрываются.

Размеры и отделки можно менять в обоих режимах. Скрытые фасады тоже получают
изменения: при возвращении внешнего вида их размер и материал актуальны.
Переключатель не сбрасывает камеру и не вызывает повторной загрузки GLB/PBR.

Режим осмотра — состояние представления, отдельно от комплектации мебели.
В пределах открытой страницы он сохраняется при переходе между шкафами.
После обновления страницы или открытия ссылки используется внешний вид;
размеры и выбранные покрытия восстанавливаются обычным способом. Кнопка
сброса конфигурации меняет размеры/материалы, не выбранный способ осмотра.
В готовых столах и сборщике столов этого переключателя нет.

## Контракт и воспроизведение

Лёгкое описание `FurnitureDefinition.interiorView.hiddenNodes` перечисляет
узлы дверных сборок, скрываемые для осмотра. Поле опционально: модели без
такого контракта работают как прежде. Генератор
`assets/source/wardrobes-integration/generate_runtime.py` получает имена
из `model-contract.json → doors`; в runtime нет угадывания по префиксам.

`createFurniturePresentation` меняет только `visible` этих узлов. При возврате
или освобождении модели восстанавливает исходную видимость, не затрагивая
трансформации, материалы и видимость остальных деталей. Отсутствующий узел
считается ошибкой контракта. Изменение вида во время загрузки применяется
к модели после завершения загрузки; ради переключения запрос не перезапускается.

Для новых моделей нужно подготовить отдельные дверные сборки, включить в них
ручки и прикреплённую фурнитуру, указать реальные имена узлов в контракте.
После пересборки исходников запустить:

```powershell
python assets/source/wardrobes-integration/generate_runtime.py
npm test
npm run build
```

## Открывание дверей — следующий отдельный этап

У всех трёх шкафов уже подготовлены вертикальные дверные pivots и направления
открывания; у 07 есть отдельные сборки ящиков. Это позволяет добавить плавный
поворот дверей по нажатию и перемещение ящиков без отдельных морфов.
В текущем обновлении анимация и нажатие на саму дверь ещё не реализованы.

Для этого этапа нужны: определение выбранной двери в сцене, различение нажатия
и вращения камеры, плавное движение/обратное движение, управление с клавиатуры
и общие кнопки открытия/закрытия. Проверять пересечения, поведение при resize,
смене модели и режиме наполнения. Накопленные повороты не должны попадать
в базовые преобразования контроллера размеров. Поворот вокруг подготовленной
оси — визуальное приближение, не точная механика мебельной петли.
