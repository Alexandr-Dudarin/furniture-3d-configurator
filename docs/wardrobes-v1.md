Дата: 21 сентября 2026. Основа: принятая пользователем поставка Loading v1.

## Что подключено

В каталоге появились категории «Столы» и «Шкафы». Зарегистрированы:

| ID | Модель | Базовые Ш × В × Г, мм | Диапазоны Ш / В / Г, мм |
| --- | --- | --- | --- |
| wardrobe-07-center-drawers | Шкаф с центральными ящиками | 1601 × 2052 × 480 | 1400–2000 / 1900–2400 / 400–650 |
| wardrobe-08-four-door | Четырёхдверный шкаф с длинными ручками | 1600 × 2200 × 520 | 1400–2000 / 1900–2400 / 400–650 |

Все размеры в метрах внутри программы; UI — миллиметры, шаг 1 мм. Для 07
сохранена глубина 480 мм из принятого model package: ранняя карточка 462 мм
не используется как основание самовольно пересоздать геометрию. Изменяются
габариты с сохранением толщины плит 16 мм, радиуса кромок, конструктивных
зазоров и сечений фурнитуры. Количество полок, дверей и ящиков фиксировано.

Корпус/полки, фасады и фурнитура имеют независимые slots. Пять матовых
неметаллических отделок плит зарегистрированы отдельно от металлов. Три
серых default соответствуют исходным цветам пакетов. Для дерева доступны
натуральный, серый, светлый серебристый и чёрный дуб: карты совместимы с
направлением волокон V в панелях. Орех с направлением U не включён, пока
не подготовлен согласованный вариант всех PBR-карт. Исходные текстуры столов
и их настройки не менялись. Цвета — цифровые отделки каталога, а не гарантия
колориметрического совпадения с образцом производителя.

## Точный UV-контракт

Раньше `textureAxes` пересчитывал tiling относительно всего габарита предмета.
Для шкафа этого недостаточно: центральная дверь, полка и неподвижная кромка
имеют собственные длины и перемещения. Общее поле `textureTransforms` содержит
bindings U/V с длиной сегмента, коэффициентом растяжения, сдвигом и anchor.
Runtime пересчитывает repeat/offset всех карт от исходных значений. Повторный
refresh и замена соседнего материала не накапливают трансформации.

`wardrobes.integration.test.ts` проверяет каждую вершину панелей относительно
физической длины поверхности, включая дуги скруглений. Погрешность менее
0,000001 UV-единицы при min / intermediate / max / return и смене материалов.
Это проверка геометрии против UV, а не только повторение формулы из runtime.

## Загрузка, камера и сохранения

`catalog.ts` содержит лёгкое описание модели для UI и сохранений. Метод
`loadRuntime()` загружает `runtime.ts`, который объединяет исходный `config.ts`,
semantic targets и `textureTransforms.ts`. UI не подтягивает полные правила
трёх шкафов при первом открытии столов. GLB также загружается только по выбору.
До `createFurnitureController` нужно дождаться полного runtime definition.

Объекты scene/renderer/camera остаются общими. Для шкафа камера помещает в кадр
его максимальный размер; движение ползунков её не сбрасывает. При смене модели
шкафа/размера viewport кадр пересчитывается. Возврат к столам восстанавливает
их прежнюю позицию камеры и target. Формат сохранений v2 не менялся;
новые модели используют существующий путь localStorage, share и reset.

## Источники и воспроизведение

При первой интеграции три GLB были сохранены без изменения геометрии.
В отдельном Chelsea back fix v1 задняя стенка 09 заменена цельной панелью
по запросу пользователя; 07/08 сохранены. Исходники и привязки UV обновлены.
Production-обвязка вынесена в отдельные файлы, поэтому запуск генератора
модели не затирает её интеграцию. После изменения модели сначала пересобрать
её исходным генератором, затем из корня проекта:

```powershell
python assets/source/wardrobes-integration/generate_runtime.py
npm test
npm run build
```

Скрипт читает актуальные `config.ts` и `model-contract.json`, генерирует
`catalog.ts`, `runtime.ts`, `textureTransforms.ts` для каждой модели.
После изменений контракта повторно проверить браузер и обновить отчёт.

Review-отчёты исходных пакетов исторические: их `REQUIRES_ENGINE_EXTENSION`
описывает состояние до интеграции. Старый `check_runtime_compatibility.ts`
намеренно проверяет устаревший `legacyTextureAxes` и возвращает код 2;
он не является проверкой новой поставки. Актуальная проверка —
`node scripts/check-chelsea-back-fix-v1.cjs`, тесты, сборка и
[отчёт интеграции](../assets/source/wardrobes-integration/validation-report.md).

## Границы этапа

Двери и ящики по умолчанию закрыты. В следующем обновлении interior view v1
добавлен осмотр наполнения со скрытыми дверями; интерактивное открывание
остаётся отдельной функцией. Существующие pivots сохранены. GLB доступны для
импорта в Blender, но Blender export/reimport в этом этапе не выполнялся.
Пакеты комодов 10–14 получены; в этом обновлении они ещё не регистрируются.
Модульные гардеробные остаются в дорожной карте.

У моделей 07/08/09 соответственно 909/579/254 primitives. При исходной
интеграции в сцене с одним shadow pass измерены 1819/1159/553 draw calls
(у 09 тогда было 276 primitives, после исправления измерено 509 draw calls): это существенная стоимость
рендера, несмотря на небольшое число треугольников. FPS на физическом телефоне
не измерялся; уменьшать число вызовов нужно отдельно, сохраняя управление
сегментами. Проверка повторных переключений подтвердила стабильное число
GPU-текстур и освобождение геометрии прежней модели.

## Chelsea back fix v1

Интеграция шкафов принята и закоммичена пользователем. Следующее отдельное
исправление заменяет две панели и профиль «Челси» одной стенкой. База панели
800 × 1948 × 3 мм, габариты шкафа и сохранения прежние. Дополнительная
проверка лучами подтверждает отсутствие отверстия по центру на base/min/max
и после возврата. Текущая проверка: 225 тестов, сборка и WebGL.
Подробности — [отчёт модели 09](../assets/source/wardrobe-09-chelsea-two-door/validation-report.md).
Старый checker wardrobes v1 хранит хеши предыдущего выпуска; после установки
исправления ожидаемо покажет отличия. Использовать новый checker, указанный выше.
